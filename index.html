3D Part DecompositionWork in progress

Decomposing a shape into parts from one click per part

A frozen TripoSG shape VAE supplies the geometry. On top of it, a small trainable head turns a single surface point per part into a clean partition of the object’s interior — no part templates, no fixed part vocabulary, and no change to the backbone that produced the shape.

Architecture

The backbone is used exactly as it was trained: the encoder turns a surface point cloud into an unordered latent token set, and 16 self-attention blocks refine it into a key/value cache that a query point can cross-attend for a signed distance. All of that stays frozen.

What we add is a second read of the same cache. Each prompt point is embedded and then grounded — it cross-attends the latent to become a token that stands for “the part containing this point”. A query point is then scored against every grounded prompt at once, and a softmax over parts assigns it to exactly one. Because the parts compete in a single softmax, the decomposition is a partition by construction: no gaps, no overlaps, no post-hoc merging.

Two training terms matter beyond the per-point classification loss. A soft-IoU (dice) term pushes each part to come out as one connected piece rather than a scatter of fragments. A consistency term draws two independent prompt draws of the same part toward the same grounded token while pushing different parts apart, so the answer barely moves when the user clicks somewhere else on the same part.

Overfitting experiment

Thirteen assets, 16k steps, dice weight 1.0, and one prompt point per part at inference. This measures how well the head can represent a decomposition at all, with generalisation deliberately taken out of the picture.
